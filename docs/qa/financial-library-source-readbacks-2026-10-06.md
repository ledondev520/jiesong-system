# 财务资料库来源与行级读回验收

本轮针对 `/dashboard/finance/statements` 内现有财务分析资料库。基线为 `8b16f70be58ac483b7bde7dd97880f602b8fd3c2`。资料库通过 `backend/scripts/import-financial-evidence.js` 本地CLI入库；网页是受限只读下钻。月度报表三文件预览/确认属于另一入口，本轮不重新验收或扩展它。

## 已复现并修复

1. 分类/账期组合返回零来源时，列表显示「当前筛选0份」，右侧仍保留上一份来源文件名和行。组件只在明细ID与当前来源相同时显示它，空筛选立即撤下旧来源。
2. 读取旧来源Sheet期间切换新来源，新来源已经显示后，迟到旧Sheet响应仍覆盖新明细。来源、Sheet与分页读取现在共享请求序号，旧请求和离开组件后的响应不能恢复失效来源。

两项组件回归分别在修复前失败、修复后通过。查询DTO、后端解析规则、角色、Schema和现有入库语义没有改变。文件格式调整遵循锁定的Prettier门槛。

## 真实来源链路

`backend/src/integration/financial-library-source-readbacks.integration.js` 在0700临时目录、0600 SQLite中应用全部已提交迁移。生成固定合成 `.xlsx` 总账和 `.xls` 工资，实际执行原有CLI，再通过真实Express认证GET读取，不mock服务或业务响应。另生成月度会计报表和未知名称文件，确认分别由专用模块处理/不支持而忽略。

- 干跑不改变任何表；明确确认导入2份来源、3个非空Sheet、61行及8处脱敏；重复确认全部跳过且所有字段/时间戳不变
- 来源文件名、相对路径、字节数、内容哈希与独立原始合成字节比较；总账关联已有2026-10账期，工资保留2026-09独立来源
- 总账保留物理行号1、3、4及分页尾部52–56、58；非空Sheet顺序正确，空Sheet不导入
- 固定值125.5、0、-20.25、合法null和true经CLI/HTTP/独立只读SQL一致；数字公式读取已有125.5缓存，不声称重算公式
- 两页行顺序、合计645.5及备注源行2/12、负数-7.5一致
- 工资姓名、证件号、手机与邮箱在持久化前脱敏，独立SQL行值和搜索文本均无原合成个人标识
- 分类/账期过滤返回正确来源或空列表，其他来源Sheet不会混入当前资料；不存在的来源返回404
- ADMIN/FINANCE读取相同存储事实；BOSS/PURCHASE/SALES/WAREHOUSE返回403，停用/匿名返回401；全部读取与拒绝都不写库
- 独立SQL逐表比较全部无关业务表和月度报表表不变；普通附件目录为空，原文件未归档
