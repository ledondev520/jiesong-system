# 当前采购 Excel 导入校验回归

## 当前入口与范围

- 基线：`6f3026dbde78f5d2d5ba0aaf1c37a837a1f70f86`，独立工作区与分支。
- 当前页面为 `/dashboard/contracts`，`/dashboard/purchase` 只是重定向。页面的“批量导入”通过 `purchaseService.importExcel` 上传 multipart 文件至 `POST /api/v1/purchases/import`。
- 该入口导入采购合同表头/汇总，不是 `/batch-import/purchase` 的商品明细 JSON 导入。
- 页面先显示普通/历史补录选择和取消按钮；选中文件即上传，随后显示逐行结果。没有解析后的行预览、确认提交阶段或独立 Excel 模板下载。“合同模板”是生成合同的 Word 模板，不能当作导入模板。生成工作簿使用当前采购 Excel 导出的列形状。
- 本轮只使用内存生成的合成工作簿、真实 Express/认证/multipart 以及已提交迁移创建的私有 SQLite。数据库目录 `0700`、文件 `0600`，独立只读 SQLite 连接比较落库值和时间戳；结束后清理合成上传与数据库。未读取真实业务文件，未访问生产、外部供应商、AI 提供商或用户电脑。

## 实际问题与最小修复

原实现把无法解析的非空金额转成 `null` 后按零金额保存；无法解析的非空日期按空日期保存。JavaScript 日期构造还把 `2026-02-30` 等不存在的日期自动改成其他日期。

合成 9 行请求在原代码下返回成功 8 行、失败 1 行：非法金额文本、`Infinity` 文本、布尔金额、非法日期文本、不存在的日历日/月、布尔日期及负日期序列号均被保存；只有负金额被拒绝。

独立复核又确认两类遗漏：仅含逗号的金额去掉分隔符后仍被转成零；真正的 Excel `#DIV/0!` 金额和 `#VALUE!` 日期错误单元格被 `sheet_to_json` 的空值默认抹掉，也被按空值保存。三种逗号空壳及两种错误单元格在首版修复下仍返回成功 5 行，扩展实际 HTTP 回归先复现失败后才修复。

修复仅在 `purchaseImportExportService.js` 的逐行创建前区分“可选空值”与“已提供但非法的值”，校验构造后的年/月/日与输入一致，拒绝清理后空壳金额，并在原工作表中检查金额/日期错误单元格来源（计入 `!ref` 范围起点）。非空非法金额/日期进入已有逐行错误统计；不改变角色、历史状态确认、编号分配、行级继续执行、空值默认或导入语义。

另经实际合成 OOXML 验证：数值/无类型公式没有结果缓存时，金额/日期原先也按空值保存。测试只删除指定单元格的 `<v>`，保留 `<f>`；在 `sheetStubs: true` 下它保留为带公式的 `t: 'z'`，而真实缓存零为 `t: 'n'`、计算结果空字符串为 `t: 's'`。修复只拒绝可明确识别的数值/无类型无缓存公式，按行/字段提示在 Excel 重新计算并保存；不执行公式、不改已解析的缓存结果。原代码在新增两行可识别无缓存公式 HTTP 用例中先复现成功 2 行，再由修复拒绝。

读取器限制：`t="str"` 公式缺少 `<v>` 与合法空字符串缓存 `<v></v>` 都会读取成相同的 `t: 's', v: ''`。无法据此区分缺缓存和真实计算后空字符串，本轮保留空字符串兼容，不新增生产端原始 OOXML 解析或猜测策略。因此证据只覆盖可识别的数值/无类型公式 stub，不能声称拒绝所有可能的缺缓存公式。

## 六类 HTTP/SQLite 用例

1. 有效工作簿：数值金额 `0`、文本金额 `1,234.50`、Excel 数字日期、`yyyy/MM/dd` 文本日期、有效闰日、缓存金额/日期公式、缓存零和计算后空字符串、空/空白/`null`/省略的可选日期与金额、空状态/备注、文本编号 `000001` 和备注内侧空格均保留既有行为。既有合同所有字段不变。
2. 缺供应商表头、只有表头和未选择上传文件分别返回 `400`，完整业务快照不变。
3. 缺供应商名称、供应商不存在或状态无效只拒绝对应行；前后有效行提交，Excel 原始行号准确。
4. 二十二种非法金额/日期全部拒绝，含逗号空壳、真正的 Excel 错误单元格、零/溢出/虚构日期序列号、非闰年及零日/月边界、无结果缓存公式；完整业务快照不变。再把同样二十二行放在两条有效行之间，仍只写入前后有效行。各拒绝行无合同头或其他部分业务写入，原记录所有字段与时间戳不变。另用 `C3` 起点工作簿验证错误单元格检测不因范围偏移而漏过，显示行号继续沿用原有范围相对编号。
5. 显式编号首次成功、重传逐行提示编号已存在且快照不变；空编号重传各生成新合同。这是原有重复导入行为，不能宣称文件级幂等。
6. 普通已完成状态导入失败，采购员显式历史选项返回 `403`；管理员显式历史选项可保留完成状态。

以上始终比较采购明细、供应商、商品、库存、到货、到货明细、验货与付款表；汇总导入与历史补录均不补造这些来源记录。

## 数字与日期解释边界

- 已验证 `1234.5` 数值及 `1,234.50` 文本，后者是逗号千位分隔符、点小数分隔符。原解析器去掉逗号后调用 `Number`，本轮未改成地区相关的数字解释；点千位/逗号小数等其他地区格式仍有歧义，应由业务规则另行确认。
- 日期保留现有 Excel 序列号和 `yyyy-MM-dd` / `yyyy/MM/dd` 路径。验证在 `TZ=UTC` 下运行；未新增时区转换、默认日期或其他日期格式。
- 无行预览或文件级幂等能力，本轮不添加这些功能。
