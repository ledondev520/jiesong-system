## 汇总优先级（P0/P1）

### P0（先改）
1. `OPS-EXEC-03` 台账状态与当前代码能力失真（需恢复能力或回退台账状态）。
2. 旧导出路由旁路：`/api/v1/export/:type` 仅认证无授权，可能绕过系统导出 RBAC+审计。
3. 种子脚本弱默认密码：`DEFAULT_ADMIN_PASSWORD` 缺失时回退 `123456`。
4. 登录快捷模式明文密码落地 `localStorage`。
5. 移动端 dashboard 缺全局导航入口（`md` 以下隐藏侧栏但无替代菜单）。
6. 财务与经营执行模块语义冲突（`ops-execution` 使用 `FINANCE_TABS` + `moduleName="财务"`）。

### P1（第二批）
1. 配置中心分域仅后端半落地，前端仍大量依赖扁平 `/system/configs`。
2. `SystemConfig` 仍承载业务结构数据（模板/映射），建议抽专表。
3. 覆盖率门禁仍偏弱（前端口径与阈值、后端 CI coverage gate）。
4. 大文件复杂度治理继续失守（多处 >500 行）。
5. 顶层 IA 偏离既定简化方案，工作台任务中枢能力不足。
6. AI 助手产品边界问题升级（默认挂载、暴露 reasoning、内部跳转方式）。

## 新发现（相对上一轮）
1. 安全旁路比上一轮更严重：旧导出路由可绕过新加固链路。
2. 文档/配置/schema 的“单一事实源”失效，数据库底座描述出现冲突。
3. 治理台账和代码真实状态脱节，影响发布可信度与验收判断。
4. 设计层面从“视觉一致性问题”转为“信息架构与任务流漂移”。

## 建议执行顺序
1. **48小时内关 P0 安全与台账一致性**（导出旁路、弱口令、明文存储、OPS-EXEC-03状态）。
2. **一周内关 P0 体验断点**（移动导航、模块语义冲突）。
3. **两周内推进 P1 结构治理**（配置分域前端接入、SystemConfig拆表、coverage gate、IA收口）。
