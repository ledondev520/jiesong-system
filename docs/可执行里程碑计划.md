# 可执行里程碑计划（V1）

> 若本文件夹结构或内容变化，请更新 `docs/README.md` 与根 `README.md` 的文档导航。

## 目的/边界/职责

- **目的**：将未来 2 周系统演进拆为可执行、可验证、可回滚的里程碑批次。
- **边界**：基于当前仓库（frontend/backend/docs）、已有子代理、质量门禁与回滚策略。
- **职责**：作为架构总控的调度清单，供各 agent 直接执行。

## 时间范围

- **起始**：2026-02-12
- **结束**：2026-02-26
- **周期**：14 天，6 个里程碑（按 2–3 天/批次）

---

## 里程碑总览

| 里程碑 | 日期 | 目标 | 主责角色 |
|--------|------|------|----------|
| M1 | D1–D2 | 架构基线固收与里程碑计划落地 | system-architect-orchestrator |

| M6 | D11–D14 | 采购链路规模化复制与文档收口 | system-architect-orchestrator + frontend-polish-engineer + backend-system-engineer |

## M1：架构基线固收与里程碑计划落地

**日期**：D1–D2（2026-02-12 ~ 2026-02-13）

### 目标

- 固化 WU 模板（输入/输出/验收脚本/回滚点）。
- 产出可执行里程碑计划，衔接《系统架构落地执行方案》中 WU-F-01。

### 涉及角色

| 角色 | 职责 |
|------|------|
| `system-architect-orchestrator` | 主责：输出里程碑计划、WU 模板、调度清单 |
| `quality-verification-guardian` | 协同：评审验收脚本与回滚点 |

### 输入

- `docs/系统架构落地执行方案.md`
- `PLAN.md`、`TASKS.md`、`METRICS.md`、`progress.md`
- 当前前端/后端/CI 状态

### 输出

- `docs/可执行里程碑计划.md`（本文件）
- 更新 `docs/系统架构落地执行方案.md` 中 WU-F-01 为 DONE
- `docs/README.md` 与根 `README.md` 导航更新

### 验证命令

```bash

test -f docs/可执行里程碑计划.md && head -50 docs/可执行里程碑计划.md

# 2. 根 README 含本计划入口
grep -q "可执行里程碑计划" README.md
```

### 风险与回滚

| 风险 | 对策 | 回滚 |
|------|------|------|
| 里程碑计划与实际节奏不符 | 按 D3 执行反馈微调 M3–M6 日期 | 回退本文件为上一版本，恢复 WU-F-01 为 Pending |

## M2：采购链路 API 契约与联调面板

**日期**：D3–D4（2026-02-14 ~ 2026-02-15）

### 目标

- 定义采购链路核心 API 契约（请求/响应/错误码）。
- 产出联调面板（READY/BLOCKED/DONE），供前后端对齐。

### 涉及角色

| 角色 | 职责 |
|------|------|
| `api-contract-coordinator` | 主责：契约文档、联调面板 |
| `backend-system-engineer` | 输入：当前采购接口实现 |
| `frontend-polish-engineer` | 输入：当前采购相关调用 |

### 输入

- `backend/src/routes/*` 采购相关路由
- `frontend/src/services/*` 采购相关 API 调用
- `docs/技术方案.md` 中的 API 设计

### 输出

- `docs/api-contracts/采购链路契约.md`（新建）
- `docs/api-contracts/采购链路联调面板.md`（READY/BLOCKED/DONE 状态表）
- 更新 `docs/README.md` 文件清单

### 验证命令

```bash
# 1. 契约文档存在
test -f docs/api-contracts/采购链路契约.md

# 2. 联调面板存在且含状态列
test -f docs/api-contracts/采购链路联调面板.md && grep -q "READY\|BLOCKED\|DONE" docs/api-contracts/采购链路联调面板.md
```

### 风险与回滚

| 风险 | 对策 | 回滚 |
|------|------|------|
| 契约与现有实现偏差大 | 先以现状为准，再标记待演进项 | 删除 `docs/api-contracts/` 下新建文件，恢复文档清单 |

## M3：后端采购链路接口加固

**日期**：D5–D6（2026-02-16 ~ 2026-02-17）

### 目标

- 按 M2 契约加固采购相关接口（错误处理、参数校验、响应格式）。

### 涉及角色

| 角色 | 职责 |

### 输入

- `docs/api-contracts/采购链路契约.md`
- `backend/src/routes/purchase*.js` 等采购路由
- `backend/src/services/*` 采购相关服务

### 输出

- 采购相关路由/服务代码更新
- 采购相关单测新增或补充（若存在）

### 验证命令

```bash

# 预期：全部通过，无新增失败
```

| 风险 | 对策 | 回滚 |
|------|------|------|
| 接口变更影响前端调用 | 变更前须经 api-contract-coordinator 确认 | `git checkout -- backend/` 回滚本轮后端改动 |

## M5：端到端冒烟与发布结论

**日期**：D9–D10（2026-02-20 ~ 2026-02-21）

### 目标

- 执行全量质量门禁（后端单测、前端单测、E2E 冒烟）。
- 产出发布结论（Go/No-Go）及证据。

### 涉及角色

| 角色 | 职责 |
|------|------|
| `quality-verification-guardian` | 主责：执行门禁、产出报告 |
| `system-architect-orchestrator` | 协同：审阅报告、决定发布节奏 |

### 输入

- 当前代码库（含 M3、M4 改动）
- M2 联调面板最终状态

### 输出

- `docs/quality/发布结论_M5_YYYYMMDD.md`（新建）
- 内容含：门禁通过情况、失败项、建议（Go/No-Go）
- 更新 `METRICS.md` 本轮质量指标

### 验证命令

```bash
# 1. 后端单测
cd backend && npm run test
# 预期：全部通过

# 2. 前端单测
cd frontend && npm run test
# 预期：全部通过

# 3. E2E 冒烟
cd frontend && npm run test:e2e
# 预期：全部通过（或明确记录已知失败项及原因）
```

### 风险与回滚

| 风险 | 对策 | 回滚 |
|------|------|------|
| E2E 偶发失败 | 执行 2 次取稳定结果；记录环境要求 | 按失败项回滚对应 M3 或 M4 |
| 单测回归失败 | 先修复再发布 | 发布结论为 No-Go，阻塞至修复完成 |
