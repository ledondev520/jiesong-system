# 三角色修复验收

本轮已解决《三角色用户体验检查》中确认的缺陷及已有能力的操作闭环缺口，按采购、财务、老板三条线实施并按功能分批提交。保留同期已完成的手机样式改进及其他任务改动。

验收日期：2026-10-01。没有修改数据库 schema、执行迁移或 db push，没有新增依赖，没有修改产品 AI 模型、供应商或部署配置。原3000/3001服务保持原状；验收使用独立源码前端3002及独立API3007，API通过导入app启动，未启动后台任务。浏览器读取现有业务数据，提交/入库/付款等写路径使用合成数据与隔离测试验证，没有保存真实交易或原始财务材料。

| --- | --- |
| 毛利直接跨币种相减、收入与成本不匹配 | 复用单柜财务计算，按已发运三状态与上海日期区间汇总自有商品CNY收入及对应成本；缺汇率/成本显示待核验，不加入预计退税或经营费用。 |
| 逾期规则不一致 | 报表和通知复用财务规则，明确“发运超过30天仍未收齐”；采购风险明确为交期已过待付，不假称已核对合同付款期限。 |

| 历史通知前50条截断、标题不可搜 | 服务端分页及标题/内容/类型检索，业务链接可追溯；实际第4页及检索请求通过，无已读写入。 |

| 风险数字不能定位业务 | 经营期间筛选和风险/销售/成本/现金钻取接到既有明细；报告→出口实际传递相同三状态、上海期间与页码。 |
| 商品/低库存/在途口径错误 | 商品数为活跃商品，低库存复用INBOUND汇总且含零库存，在途仅SHIPPED；低库存页面与汇总同规则、真实查询成功。 |

| 英文面包屑 | 补当前使用的中文路由名称，组件检查通过。 |

## 验证结果

- 前端：180个测试文件、731项检查全部通过。
- 后端：582项检查全部通过。金额、库存、日期、全量分页与状态边界的新增回归先表达原失败，再修复；样式使用实际页面复验。
- TypeScript检查通过；独立源码副本的Next.js生产构建（webpack）通过，不覆盖现有服务的.next目录。
- 三个子代理分别完成桌面/390×844浏览器验收；只保存结构、布尔结果、尺寸及脱敏结论，没有保存实际金额、账号、合同号或财务原件。
- 按功能拆分本轮提交；仅提交本任务文件，其他任务改动保留。代码验收完成，本轮没有部署上线。

## 仍需业务确认的建议与验收边界

原报告已把以下内容列为待确认业务需求，而不是已确定程序错误：分批到货、验货不合格与退货；独立老板只读角色；客户信用管理和未来现金计划。本轮为整单收货增加“已到齐且验收合格”的前置确认，未自定不合格货处理或分批库存政策。相关问题已向用户询问，尚未收到业务规则。

真实PURCHASE/FINANCE独立账户、实际保存交易、外部盖章、税局申报、真实手机软键盘和系统手势不在本次实际验收结果中。写操作以隔离检查验证；外部法规与办理要求没有作为已认证结论。新经营前后端接口需要一起更新，本轮独立预览已经验证完整配套。
