# 本地系统走查与性能优化

本轮完成前端操作、后端接口与性能三个方向的并行走查，并实施可复现问题的最小修复。没有新增依赖、缓存层、索引或数据库迁移，没有修改真实业务记录；写操作与文件生成验证使用受限目录中的 SQLite 副本，副本和测试附件随后删除。

## 运行与覆盖

- 本轮最新前端快照：`http://localhost:3003`；源码后端：`http://localhost:3006`。保留先前会话的服务与前端改动，隔离构建目录以避免 Next.js 锁和旧构建干扰。此后端入口不重复启动已有定时任务。
- 浏览器实际覆盖 20 个主页面：工作台、采购、供应商、库存、出口、HS、退税、财务概览、月报、收付、流水、发票、对账、经营执行、用户、设置、商品、日志、通知、AI。实际验证库存翻页及 20/50 条切换、搜索与重置、HS 数字前缀、移动端基础浏览、断网提示及恢复。
- 只读基线包含 122 个 HTTP 用例，119 个 200、3 个预期 404；无数据的详情成功场景单独标记，未以 404 充当成功详情验收。修复后的权限、分页、日期等 14 项 HTTP 复验通过。
- 116 个隔离写操作覆盖基础资料 CRUD、采购状态与生产资料、入库、出口/装箱、报关及退税草稿、收款分配、附件与导出等。首轮 115 成功、自动对账超时；随后慢点隔离复测 23/23 成功。上传附件使用合成字节，不读取原始业务文件。
- 补充导出/下载、会生成通知的工作台统计，以及合成 WAREHOUSE 账号的权限检查，均在数据库副本进行。文件测试区分真实生成 PDF/Excel 的签名与合成附件的原始字节一致性，不把任意假 PDF 字节声明为可渲染文件。
- 最终导出/下载补验为 18 项基础用例加 15 项补充用例，33/33 通过；三个附件下载均 200 且原始字节一致，目录 0700、文件 0600；非 ADMIN 的四项受限读取均预期 403。GET 路由去重覆盖 137/140，包含 source 补测中的退税逐合同发票核验（200、46ms）；剩余三项为外部 AI greeting、greeting stream 与 HSCIQ detail。
