# 采购、库存、销售与退税准备走查

本地合成业务已贯穿采购、分批验货、两次出口、收付结清与退税材料归档。本轮发现的问题已修复。上海税务平台登录、正式提报和真实业务数据尚未验收，不能据此宣称“出口退税已全自动上线”。

## 范围与环境

- 2026-10-02；冻结源码副本位于系统临时目录，数据库从 schema 创建为空库，附件与身份全部合成。没有读写生产业务库，没有部署。
- 基线为 `dd83a94` 及当时工作区中的分批验货/老板只读改动；后者随后提交为 `69f67ad`、`b2f2fad`。本轮修复为 `d6dfd56`、`fe4ca8e`、`75adf52`、`8122f84`。
- 后端真实 Express/SQLite；前端先开发模式走查，再以 webpack 生产构建运行。浏览器桌面 1366px、手机 390px；本地回环网络，无限速，非大数据压测。
- 六个合成角色实际登录：管理员、采购、仓库、销售、财务、老板。复用现有依赖和供应商配置，不修改模型、密钥或部署环境。并行任务的依赖文件改动未归入本提交。

## 主业务及请求覆盖

| 旅程 | 调用链与写入 | 已验证的结果 | 检查等级 |
| --- | --- | --- | --- |
| 创建采购、签约、生产资料保存并完工 | purchases → 采购服务/生产资料 | 一次保存完工，资料留存，进入 READY | 真实 HTTP/SQLite、页面读取 |
| 分批到货、验货、复验 | purchases/:id/receipts → purchaseReceiptService | 待验/待复验不能入库，合格增量入库，真实认证角色限制 | 真实 HTTP/SQLite、六角色权限 |
| 分批出口与三单生成 | sales/import-purchase-items、export-packet | 同一采购分两次各出一半；装箱自动进入 PACKING；真实 XLSX 生成 | 真实 HTTP/SQLite、页面读取 |

| 付款、收款、到港 | finance/payments、sales/status | 实际款项登记后自动结清；付款与收款不额外手改完成状态 | 真实 HTTP/SQLite、收付页面 |

| 发票与船司材料 | bank-flow/invoices/import、packing-list-check | XLSX 实际导入并核验；PDF 实际解析比对与受限归档 | 真实 HTTP/SQLite、发票页面 |
| 出货确认与月度清单 | tax-refunds/workbench/preparation、confirm、monthly-export、files | 材料齐套一次确认；重试复用归档，旧版本拒绝；相同事实重复保存不重确认；月度两条出货均已确认 | 真实 HTTP/SQLite、浏览器实际下载 |
| 库存手工/AI入口 | inventory/status、batch-status、Agent 确认执行 | 采购/验货来源拒绝手改状态；确认执行重新检查来源；同状态保留 FIFO 时间 | 真实 HTTP/SQLite、页面与回归测试 |

常规接口的浏览器样本耗时为数毫秒至数十毫秒；这是小规模本地样本，不能当线上性能保证。开发页面首次编译另计，不能与生产可操作时间混用。未获取每个页面首反馈/首有效结果的独立时点，不报告 p95。

## 原问题与修复

| 问题 | 修复前证据 | 修复及复验 |
| --- | --- | --- |
| 装箱发运绕过库存且派生金额被清零 | 只有部分合格库存仍返回发运成功；旧代码只读取空的 SalesItem | 以自有 packingItems 分配对应采购来源/单位库存；不足返回 400，两次出货总量守恒，价格保留 |
| 草稿编号重复、替换可删正式记录 | 第二份出口草稿唯一性冲突；替换没有检查状态 | 编号含合同号，原子嵌套更新，已放行返回 409 |
| 相同资料保存触发重新确认 | production-details 保存相同事实后 sourceVersion 改变 | 排除技术 createdAt/updatedAt；业务日期、金额、状态、文件等仍参与版本 |
| 请求与文件代理基址不一致 | 裸后端地址导致登录路由 404；完整 API 地址被代理重复拼接 | 共享解析，裸 origin 补 /api/v1，显式自定义路径保留；真实登录与三种下载成功 |
| Agent 上游错误返回空成功 | 上游连接错误，外层仍 200、空文本 | 直接检查 query 终止事件；失败不写成功记录，普通/流式故障回归通过 |
| 库存状态独立于业务事实手改 | 共享状态机允许采购运输中直接设为入库 | 来源约束覆盖普通、批量、AI入口；业务库存展示自动流转，禁止重复手改 |

## 页面、权限与恢复

实际打开采购清单及详情、供应商、商品、库存、出口清单及详情、报关/退税工作台、财务概览、收付、发票、银行流水、对账、财务报表、经营报表、HS、物流、AI及会话、系统配置、分类、港口、报关公司、导出、账号、日志和通知。页面读取未见接口 4xx/5xx；有数据页核对合成记录，空数据页只能证明读取/空态可用，不能证明所有业务表单分支通过。

六角色登录与角色主页面通过；老板的出口、库存、财务报表页面不展示业务写按钮，直接进入 AI/配置页回到工作台。后端另验证老板写入及 AI 403、财务/销售登记验货 403、销售票面清单 403。

浏览器实际下载的月度 XLSX 含两条出货，材料和归档 XLSX 含准备清单、关联发票、规则口径、出货关联、发票核验。数据库附件目录 0700、文件 0600。手机材料弹窗宽 390px，无横向溢出，关闭与下载控件可定位。截图工具的 Page.captureScreenshot 超时，因此像素视觉验收未完成；没有把 DOM 验证当作截图验收。

退税工作台离线查询显示断网及读取失败，月份和关键词保留；恢复网络后用键盘重试，原月份和搜索词保持，返回一条匹配出货；鼠标操作被浏览器自动化层判定有遮挡，未将这项记录为鼠标恢复通过。没有模拟银行/税局已受理，没有提交真实税务数据。

## 自动化与人工边界

| 自动执行 | 仍须有真实依据的业务确认 |
| --- | --- |
| 生产保存与完工合并、装箱进入下一状态、验货合格增量入库、发运扣库、款齐结清 | 成交条款与签署、实际验货合格数量、实际发运/到港、实际款项 |
| 三单、关联清单、发票机器核验、材料归集、内部草稿、确认后的归档/月度汇总 | 资料差异与缺件、签署件/运输凭证、正式申报的业务授权 |

AI 可辅助抽取和匹配，不能凭空生成“已付款、已验货、已发运”事实。当前实际供应商只读查询已通过，AI 所有写工具的真实模型执行仍未全量测试。
