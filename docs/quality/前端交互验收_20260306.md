# 前端交互验收 2026-03-06

## 目标
- 基于仓库现有 Playwright 资产与补充脚本，验证前端关键交互是否达到“可用且可继续操作”的状态。
- 聚焦桌面端主流程、移动端首屏可达性、键盘焦点链与基础无障碍语义。

## QA Inventory
- 用户可见声明
  - 登录页可通过键盘进入主要输入与提交控件。
  - 桌面端工作台首屏可见，并可进入通知/日志/导入记录关键交互。
  - 移动端至少应暴露一个可见的全局导航入口，保证用户不依赖桌面断点也能继续操作。
- 关键控件/状态
  - 登录：用户名、密码、记住密码、登录按钮、注册链接。
  - Dashboard：侧边导航、Header 搜索、通知、用户菜单。
  - 系统管理：通知中心的“仅未读/标记已读”、系统日志筛选、导入记录状态筛选。
- 探索场景
  - 通知中心切换到“仅未读”后继续执行“标记已读”，确认空态可达。
  - 移动端 390x844 首屏检查是否仍能找到主导航入口。

## 执行方式
- 现有广覆盖用例：
  - `cd frontend && npx playwright test e2e/smoke.spec.ts --reporter=list`
  - `cd frontend && npx playwright test e2e/button-coverage.spec.ts --reporter=list`
- 补充交互验收脚本：
  - `cd frontend && node scripts/interactive-qa-audit.mjs`
- 说明
  - 本轮优先尝试 `playwright-interactive` 技能要求的 `js_repl` 持久会话。
  - 当前环境的 `js_repl` 无法解析仓库内 `frontend` 局部安装的 `playwright` 包，因此改为仓库内可复跑脚本补齐“桌面/移动端/键盘”验收。

## 验证结果
- 通过
  - `smoke.spec.ts`：14/14 通过。
  - `button-coverage.spec.ts`：38/38 通过。
  - 补充脚本成功产出桌面登录、桌面工作台、通知中心、移动端工作台截图与 `summary.json`。
- 未通过
  - 发现 2 个真实可访问性/可用性缺口，详见下节。

## Findings
1. 高优先级：移动端工作台无全局导航入口
   - 证据：`frontend/qa-artifacts/interactive-qa-20260306/mobile-dashboard.png`
   - 代码定位：
     - `frontend/src/app/dashboard/layout.tsx` 在 `md` 以下隐藏侧边栏。
     - `frontend/src/components/layout/Header.tsx` 当前只提供搜索、通知、用户菜单，没有补位的移动端导航开关。
   - 影响：用户进入工作台后无法继续切换采购、销售、库存、系统管理等主模块，移动端不可完整使用。
2. 中优先级：登录页“记住账号和密码”复选框缺少可读名称
   - 证据：`frontend/qa-artifacts/interactive-qa-20260306/summary.json` 中 `checks.login.tabSequence[2]` 的 `name` 为空。
   - 代码定位：`frontend/src/app/(auth)/login/page.tsx` 中 `Checkbox` 与 `FormLabel` 未形成稳定的可访问名称关联。
   - 影响：屏幕阅读器/键盘用户命中该控件时无法获知语义。

## 结论
- 桌面端关键交互链路当前可用，现有 E2E 广覆盖也基本稳定。
- 但“前端交互已完整、用户可无障碍使用”这个结论当前不能成立，至少需要先修复：
  - 移动端全局导航入口缺失。
  - 登录页 rememberMe 复选框的可访问名称。
