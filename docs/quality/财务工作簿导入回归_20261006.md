# 财务工作簿导入回归（2026-10-06）

## 结论与修复

真实合成 XLSX 证明原月报解析把 ExcelJS 公式对象直接交给 `Number(value)`，丢弃已保存的数值缓存。资产/负债/权益总额因此误报缺失；可选收入、成本、费用、现金流则可能变成空值，预览成本合计也受到影响。

修复只调整 `backend/src/services/financialStatementsService.js` 的工作表金额读取边界：
- 公式通过公开 `cell.result` 读取已保存的有限数字，保留0、负数与小数
- 字面量与真正空单元格继续使用已有转换语义，不计算公式或改变报表/借贷规则
- 仅当公式 `result` 为undefined时，惰性使用服务已安装/使用的SheetJS检查字符串空结果，保持合法空字符串公式的旧空值兼容
- 可区分的缺缓存、错误缓存（如 `#DIV/0!`）及文本/布尔等非金额结果返回400；指出Sheet、行、单元格和金额列，要求重新计算并保存后重试

### 明确残余边界

原生ExcelJS写出的字符串空缓存含 `t="str"` 与空 `<v></v>`；删除 `<v>` 但保留字符串类型后，ExcelJS仍返回undefined，SheetJS也把两种输入都返回为字符串空值。既有公开接口不能区分这两种情况。本次保持旧空值兼容，返回/存储null，不推测0，不声称所有缺缓存都可检测，也没有新增XML解析器或依赖。

## 新增真实验收

入口：`backend/src/integration/financial-workbook-import.integration.js`，十个子用例，连同外层测试共11项。所有源文件在内存生成，SQLite使用临时0700目录/0600文件及已提交迁移；独立只读连接比较全部行和时间戳。单文件/数据包成功写入、合法空值、两类覆盖及回滚后重试还直接把SQL中的资产、月度/YTD、0、负数、现金流和证据金额与夹具字面量对照。三来源类型、固定文件名、Sheet与计数直接在SQL中核对，大小/SHA-256与原合成文件独立比较；保留所有HTTP断言，避免读取服务掩盖写入错误。
