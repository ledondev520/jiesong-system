# 批量导入档案与库存期初

管理员打开「系统配置 → 数据导入导出」的批量导入区。先下载模板，填写后点击「校验并预览（不落库）」。修正错误后重新预览，最后点击「确认导入」。预览和模板下载都不写数据库，包括审计表。

## 模板字段

模板只有表头，没有会被误导入的样例数据。保留全部表头，选填列可以留空。不要增加额外列。

| 类型 | 必填字段 | 选填字段 |
| --- | --- | --- |
| 商品 `products` | 报关名、单位 | 规格、HS编码、描述 |
| 供应商 `suppliers` | 名称 | 简称、联系人、电话、邮箱、地址 |
| 门店 `stores` | 名称、港口代码 | 联系人、电话、邮箱、地址 |
| 库存期初 `opening-inventory` | 期初编号、商品ID、数量、单位、期初日期 | 备注 |

先维护港口，再导入商品、供应商、门店，最后导入期初库存。商品 ID 来自商品 CSV 导出的 `ID` 列。期初数量必须先在线下盘点确认。

纯合成示例，不是业务数据：商品 `合成商品,规格A,件,0123456789,仅测试`；供应商 `合成供应商,合成,,,synthetic@example.invalid,`；门店 `合成门店,SYN,,,,`，其中 `SYN` 必须先在港口档案中存在。

## 校验与执行

- 支持 UTF-8 CSV 和单工作表 xlsx，上传上限 10 MB，数据最多 5000 行、100 列。不支持旧 `.xls`。xlsx 公式和错误单元格会被拒绝，先粘贴为值。HS 编码和日期单元格使用文本格式。日期为 `YYYY-MM-DD`。
- 商品按报关名、规格、单位识别已有记录。供应商和门店按完整名称识别。已有记录与文件内重复记录都报错，不覆盖档案，不自动猜测别名。
- HS 编码如填写则必须为 10 位数字。邮箱如填写则校验格式。门店港口代码必须存在。单元格上限 1000 字符。
- 期初编号使用 1 至 64 位字母、数字、下划线或连字符。它生成稳定库存 ID `opening:<期初编号>`，重复执行会被拒绝。不得换编号重新导入同一份余额。
- 库存必须引用已启用商品，单位必须一致，数量为有限正数，期初日期有效且不晚于今天。期初只能新增 `INBOUND` 数量，不是盘点调整、成本估值或采购收货。
- 期初执行要求明确勾选「我已盘点核对」。它保留期初编号、日期和备注，不生成采购合同或验货凭证。后续采购继续走既有验货流程。
- 执行重新读取并校验全部上传内容与数据库。任意一行失败，整批不保存。成功后同一事务写一条最小审计记录，只含类型、行数与管理员关联，不保存上传文件或原始行。
- 页面展示前 50 行。校验覆盖全部行；错误总数可见。执行失败后必须重新预览。网络响应丢失时先核对档案和库存，不要更换期初编号重试。

## API

所有入口要求已认证的 ADMIN。普通采购、仓库和 Agent 不获得导入权限。

| 方法 | 路径，相对 `/api/v1/import` | 行为 |
| --- | --- | --- |
| GET | `/templates` | 返回四类表头与必填字段 |
| GET | `/templates/:kind?format=csv` 或 `format=xlsx` | 下载真实模板文件 |
| POST | `/catalog/:kind/preview` | multipart `file`，只读校验，返回各行错误与 `canImport` |
| POST | `/catalog/:kind/execute` | multipart `file`，执行时重验；期初另传 `confirmOpening=true` |

旧出货汇总接口 `/preview` 和 `/execute` 保留独立业务契约。旧通用上传入口同样支持 CSV/xlsx，不把档案模板当出货汇总使用。

## 重跑验收

```bash
cd backend
NODE_ENV=test JWT_SECRET=test-only-jwt-secret-for-ci-123456 node --test src/services/catalogImport.database.test.js src/routes/dataImport.upload.test.js
```

`JIESONG_TEST_EVIDENCE_DIR` 可指定私有输出目录，测试会保存八份实际下载的模板、商品预览和期初落库读回 JSON。测试只创建临时合成数据库，结束后删除夹具。全库快照断言证明模板和预览没有副作用。
