# 出口退税两表生成与录入指引

把已核验的采购、报关资料生成税局格式的 **进货明细申报表** 与 **出口明细申报表**（俗称“两套明细单”），并给出税局录入与保存后核对的步骤。

- 进货明细申报表是 **进货（购进凭证）** 明细，不是进口报关单。
- 命令只在本机离线计算：不连数据库、不联网、不登录税局，不读 `.env`。生成文件 **不代表已录入、自检通过或正式申报**。
- 本轮不提供网页操作界面、远程浏览器或任务平台；录入由操作人按本指引完成。

## 1. 三步速查

1. 备好 `cases.json`（逐票核验后的归并结果，见第 3 节）。
2. 在仓库根目录运行（示例值需替换）：

   ```bash
   npm --prefix backend run refund:tables -- \
     --cases ~/work/cases.json \
     --period 202612 --batch 001 \
     --buyer-tax-id <本企业纳税人识别号>
   ```

3. 打开输出目录：先读 `核对结果.md`，再按第 6 节录入税局，保存后按完整关联号读回核对。

## 2. 命令与输出

等价入口：`node scripts/build_tax_refund_declaration_tables.js <参数>`。相对路径按执行命令时的目录解析，支持 `~/`。

| 参数 | 必填 | 含义 |
| --- | --- | --- |
| `--cases <json>` | 是 | 已人工核验的归并结果数组 |
| `--period <YYYYMM>` | 是 | 申报年月，保持你选定的月份；晚于核对基准日只提示 `FUTURE_PERIOD`，不会自动改月份 |
| `--batch <NNN>` | 是 | 申报批次，3 位 |
| `--buyer-tax-id <税号>` | 是 | 本次企业（购方）税号，须与每张原票购方识别号一致 |
| `--as-of <YYYY-MM-DD>` | 否 | 核对基准日，默认今天（Asia/Shanghai），只用于未来月提示 |
| `--overrides <json>` | 否 | 按完整关联号指定分批用票的比例/数量，必须写 `reason` |
| `--used <json>` | 否 | 历史正式占用台账；仅 `status=submitted` 扣占用，草稿不扣 |
| `--out-dir <dir>` | 否 | 全新输出目录；默认 `tmp/tax-refund-declaration-tables/<年月>-<批次>`（`tmp/` 已被 Git 忽略） |

输出（目录权限 `0700`，文件 `0600`；目录已存在则拒绝覆盖，不会改动原文件）：

| 文件 | 用途 |
| --- | --- |
| `外贸企业出口退税进货明细申报表_<年月>-<批次>.xlsx` | 进货明细，工作表“数据”，17 列 |
| `外贸企业出口退税出口明细申报表_<年月>-<批次>.xlsx` | 出口明细，工作表“Sheet1”，17 列 |
| `plan.json` | 可录入 `entries`、待核 `pending`、未列入 `excluded`、原票余额 `balances`、汇总 `totals`；`formal_submission` 恒为 `false` |
| `核对结果.md` | 条数、计税金额、退税测算、美元离岸价、待核项与分批余额 |

控制台只打印条数、文件名和路径，不打印税号、票号或金额；金额汇总在 `核对结果.md`。文件名前缀保持“外贸企业出口退税进货/出口明细申报表”，可被 `backend/scripts/import-tax-refund-evidence.js` 识别，用于税局受理后的证据交叉校验。

## 3. cases.json 契约

顶层是记录数组，每票一条；中文键沿用平台导出名称。金额、数量、税率推荐十进制 **文本**；票号、关联号必须是文本（保留前导零，20 位不能被 Excel 数值化）。

| 字段 | 内容 |
| --- | --- |
| `sequence`、`invoice` | 原进货序号；18 或 20 位完整进货凭证号 |
| `is_candidate`、`issues`、`notes` | 是否已核验可用；未决疑点数组；备注（写入表中“备注”列） |
| `invoice_values.live_details` | 原票明细数组，**恰好 1 行**才自动处理：`数电发票号码`、`开票日期`、`销方识别号`、`购方识别号`、`发票票种`、`发票状态`、`是否正数发票`、`单位`、`数量`、`金额`（不含税）、`税率` |
| `export` | 本次出口的 17 列字典（含 17 位 `关联号`、21 位 `出口货物报关单号`＝18 位关单号＋3 位项号）；不在本次出口范围写 `null`，进入 `excluded` |
| `customs` | 正式关单证据：`出口报关单号`、`项号`、`出口日期`、`法定单位`、`法定出口数量` |
| `rate` | 与商品和出口日期相符的税率文库记录：`CODE`、`UNIT`、`ST_DATE`、`END_DATE`、`ZSSL_SET`、`TSL`（不能用发票税收分类编码代替） |
| `form_values` | 已归并的 17 列进货预填值（商品名称取 `form_values[9]`，不被关单名称覆盖） |

关联号 17 位＝申报年月 6 位＋批次 3 位＋序号 8 位，进货、出口两表共用；其前 9 位必须等于 `--period` 加 `--batch`。

**来源与现状**：`cases.json` 由人工（或 Codex）对照证据逐票归并，当前 **没有从数据库一键生成的功能**。常用证据：出口四单（合同、发票、箱单、报关预录，见 [出口清单快速制单SOP](../出口清单快速制单SOP.md)）、进货发票明细（`npm --prefix backend run invoice:verify` 或税务数字账户导出）、解密报关 XML（`scripts/import_tax_refund_customs_xml.js`）、适用日期的税率文库。工具不替代语义审核，`is_candidate=true` 只能用于证据已核实的记录。

## 4. 计算与版式口径

- 退税率＝征税率与文库退税率 **孰低**；可退税额＝计税金额×退税率，四舍五入到分；出口表“退税额”＝同一关联号的进货可退税额（与 `import-tax-refund-evidence.js` 校验口径一致）。
- 全部使用精确十进制，不经过浮点。数量超过 5 位小数、美元离岸价超过 2 位小数时转待核（`PRECISION`），不静默舍入。
- 分批用票：`overrides` 形如 `{"<关联号>": {"fraction": {"numerator": "3", "denominator": "5"}, "quantity": "2480", "reason": "…"}}`，分母必须等于原票数量；`reason` 必填。比例只分摊金额，不推导重量；普通发票等硬错误不能被绕过。同一原票累计占用超过原票会直接报错。
- 版式按上海电子税务局（标准入口）导出的样表复刻，已逐单元格对照：进货表工作表“数据”、出口表“Sheet1”，全部单元格为文本格式，空值为单个空格，税种 `V`，数量 `#,##0.00000`、金额 `#,##0.00`（带千分位），税率去尾零；进货表宋体 12、四周细边框，出口表表头居中、正文宋体 11；列宽、行高同样样表。进货表序号按出口顺序重排为 1…n，出口表序号保留源值。
- 计算只覆盖普通购进货物、已核实税率的情形；特殊业务另按官方规则处理。“脚本通过”不等于税务机关确认可退。

## 5. 待核错误码速查

`核对结果.md` 与 `plan.json.pending` 里的错误码；有错误码的票 **不会** 进入两表。

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `INVOICE_DETAIL` | 原票明细不是恰好 1 行（多行票/无明细） | 人工拆分后补入 |
| `INVOICE_NUMBER_MISMATCH` | 明细票号与进货凭证号不一致 | 回查原票 |
| `INVOICE_TYPE` | 不是增值税专用发票（如普通发票） | 不得编入，另行核实资格 |
| `BUYER_MISMATCH` | 购方识别号与本次企业税号不符 | 回查发票与企业主体 |
| `INVOICE_STATUS` | 发票状态非“正常”或不是正数发票 | 回查红冲/作废 |
| `FORM_FIELDS` | `form_values` 不是 17 列 | 补全预填值 |
| `EXPLICIT_PENDING` | 未标记 `is_candidate` 且无指定参数 | 核验后标记，或用 `overrides` 并写原因 |
| `RATE_CODE` / `RATE_DATE` / `RATE_UNIT` | 文库代码、有效期、单位与出口不一致 | 取适用日期且细分码正确的文库记录 |
| `FORM_COMMODITY` / `PURCHASE_NAME` | 进货预填的商品代码/单位与出口不符，或进货名称为空 | 更正预填值 |
| `ZERO_REFUND_RATE` / `RATE_LEVY_BRANCH` | 退税率为 0；征税率超出文库允许的征税分支 | 回查税率证据 |
| `CUSTOMS_EVIDENCE` / `CUSTOMS_KEY` / `CUSTOMS_UNIT` / `CUSTOMS_QUANTITY` | 缺关单证据；关单号+项号或日期、单位、法定数量不一致 | 回查正式关单 |
| `MISSING_ALLOCATION` / `NON_POSITIVE_ALLOCATION` | 缺本次分摊金额/数量，或数量/金额非正 | 补 `form_values` 或 `overrides` |
| `EXPORT_PURCHASE_QUANTITY` | 进货数量与出口数量不一致 | 核实申报数量 |
| `PRECISION` | 数量超 5 位小数或离岸价超 2 位小数 | 回查原始数据，不要舍入凑数 |
| `ALREADY_SUBMITTED` | `--used` 台账显示该关联号已正式申报占用 | 确认是否重复申报 |

数据缺陷（缺字段、非法数字、重复关联号、期次与关联号不一致、同票累计超额）会直接报错并带关联号，需修正输入后重跑。非阻断提示（出口发票号含空格/冒号等非常规字符、未来月份、指定参数）写在 `核对结果.md`，请对照官方样表确认。

## 6. 税局录入顺序与保存后核对

1. 写明本次企业、申报年月、批次、两表文件位置、有效关联号范围和暂缓项。
2. 先核对或补齐 **出口明细**，再按完整关联号填写 **进货明细**；逐字段对应 17 列，不以进货流水序号代替出口关联号。
3. 列明指定分摊、未决重量、票种等特殊项；保留原备注；待核项不得混入本次有效范围。
4. 保存后按完整关联号读回两表，核对条数、数量、计税金额、退税额、美元离岸价及备注；发现冲突停止该项并回查证据。
5. 如还要生成税局草稿，再按税局流程执行并验收，如实报告完成状态。

页面操作注意（来自一次实际录入经验，页面可能变化，以现行页面为准）：

- 先确认企业、业务、申报年月和批次；清除无关筛选并调大每页条数，“当前页没看到”不能说明未录入。
- 进货序号在线上可能是流水号，按 **完整关联号** 比对，不按相邻行或序号尾号猜配。
- 关联号带出商品和单位后，再填发票、日期、供货方、数量、计税额和税率，等待自动退税额，最后填名称和备注；异步回调曾重置名称/备注，保存前读回全部字段。
- 保存后回完整列表核对；界面仍在加载或结果不明就先停止，查重后再继续，不要反复点保存。“保存并增加”可能留下沿用上一条字段的空表，不能当作已保存。
- “批量修改”曾作用于当前筛选的整表而不是勾选行，未验证范围前不要使用。
- 申报年月晚于税局系统当前月份时，税局曾返回 `Y0051`。保持你选定的月份：草稿可留存，但自检和正式申报不能视为完成；不要为绕过而改月份。
- 分别报告这几种状态：已填写、明细已保存、草稿已生成、自检排队、自检通过、已正式申报。

## 7. 文件格式与导入

- 只生成带完整版式的 `.xlsx`。税局若要求 `.xls`，用 Excel 或 WPS 打开后“另存为 Excel 97-2003 工作簿（.xls）”。
- 两表目前是 **核对和照填稿**。是否满足税局批量导入模板 **尚未验证**，未验证前不要把“导入 Excel”当作已支持的操作。

## 8. 数据安全

两表、`plan.json`、`核对结果.md` 含税号、票号和金额，按 Restricted/Confidential 处理：只放在受限输出目录，不提交 Git、不放普通附件、不贴进日志或聊天。命令拒绝覆盖已有目录；写入失败会清理本次创建的目录；错误信息里回显的输入值（票号、关单号等）只保留首尾字符，定位用的关联号完整显示。

## 10. 已知限制

- 无数据库到 `cases.json` 的自动归并；无网页自动录入；税局批量导入兼容性未验证；输出仅 `.xlsx`。
- 税局另一个导出入口（Arial、工作表名为表名、数字不带千分位）的文件格式与标准入口导出不同，本工具只复刻标准入口的样表；若税局要求后者，需另行对照调整。
- 出口发票号个别带 `NO.: ` 前缀（出货汇总原值，税局导出的明细里也出现过）。工具只提示、不改写；是否去掉前缀，请对照出口发票和税局现状决定。
- 官方导出的出口明细“退税额”列，未处理批次为 `0`、已处理批次为金额。本工具写入该关联号可退税额（与系统证据校验口径一致，也与已处理批次的导出一致）；录入时以税局页面自动带出的值为准，不要为了对齐而强改税局值。
