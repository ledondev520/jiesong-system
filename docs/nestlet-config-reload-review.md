# Nestlet same-release configuration reload review

Prepared 2026-10-07. Not dispatched. This is a dedicated maintenance-branch operation only.

Operator setup writes private configuration but does not recreate the running application. This procedure uses exactly the existing reviewed release `2fc15f216714d0331a82456edb1d97b9f76f8498`, existing local image, existing configuration and existing schema3 volume. It does not build/pull, update the release pointer, edit configuration, collect credentials, migrate/restore/delete data or change Jiesong services.

Before dispatch, the root reviewer must confirm that the operator setup helper has exited and no credential writer/new-release operation is active. The workflow requires that explicit completion input, reuses existing staging SSH/address/host-key guards and the shared Nestlet concurrency group; the host operation also takes the incremental-release lock. This lock does not control the separate interactive setup helper, so the human coordination gate is mandatory.

Checks cover managed ownership markers, exact current pointer and clean source checkout, immutable existing image identity, a single Nestlet service, expected loopback port, read-only root, exact persistent volume/mount, private file ownership/modes, schema3 identity and health. Environment-file contents and hashes are never inspected: only inode/size/nanosecond timestamps/modes are compared before and after recreation. Compose alone consumes the existing private configuration as part of starting the authorized runtime. Selected configuration queries return service/volume/image names only; parser/recreation error output is suppressed.

The only service mutation is same-image `up --no-build --pull never --no-deps --force-recreate` for Nestlet. Afterwards, loopback and public HTTPS checks require health and public booleans `authConfigured=true`, `authenticated=false`, `caseStorageEnabled=true`. Failure preserves configuration/data and reports a blocker; there is no password reset, automatic rewrite or other fallback. Recreating the application invalidates process-local sessions and loses RAM-only settings; server-provided settings are loaded from existing private configuration.

Local safety tests exercise syntax, embedded code compilation, gate rejection before host access, metadata-only lease detection including atomic replacement, fail-closed public authentication flags, fixed action scope and workflow/script digest. Actual SSH, Docker recreation and production/public checks have not been run in this preparation task. No new credential, persistent-access grant or third-party data transmission is added; the existing authorized SSH and runtime configuration paths are reused. A metadata change, unexpected runtime state or unfinished setup helper blocks the action and needs review.
