# 出货 Excel 自动生成出口三单

## 使用入口

进入「业务 → 出口订单 → Excel 出三单（管理员）」，上传出货汇总 `.xlsx`。

- 文件只有一票且资料完整：自动下载含「合同、发票、箱单」的 Excel。
- 文件含多票：选择本次 EXP，自动生成这一票。
- 需要改价：改本票单价，点「重新计算」，再下载。人工价格优先保留。
- 缺少资料、来源变化或价格约束不满足：在界面显示具体问题，补齐后重试，不猜测、不把缺失值填成0。

此入口是制单，不是合同签署、报关提交、出库或收付款。上传不改变原Excel，也不自动更新业务库的合同、库存和资金记录。

## 已确认的固定规则

1. **使用已确认的原始三单模板。** 保留抬头、字体、边框、条款、银行信息、签章位置和打印范围，只更新本票字段。超过模板行数时扩展明细并顺延合计、条款、签章区。
2. **一行源数据对应一行单据。** 不根据补充信息或备注中的多种设备、附件擅自拆行，不按同名商品自动合并。拆分必须由用户明确提出。
3. **正文保持原格式。** 不加入DRAFT、待确认、来源路径、源行号、核验说明、加价算法或风险提示。问题和计算依据显示在系统界面。
4. **保留人工修改。** Excel出口单价、本票手工覆盖价优先于自动报价，不能为了凑30%把人工价改回建议价。
5. **三单同源。** 品名、数量、单位、价格、箱数、毛净重和体积来自同一组选定源行，三张表按相同顺序联动；明细留存申报要素和货源地。

报价规则已统一：单价（USD）= 单位采购成本 ¥ × (1 + 加价) ÷ (现汇 − 0.2)，向上取整到整美元（例 1993.87→1994、6.50→7，不再取 5 的倍数）；老商品默认取上次确认价，新商品才用此公式，普通商品加价 30%、瓷砖等分类按 设置 > 报价规则 单独设置；
缺采购成本时不给建议价，需人工填写。详见 `docs/redesign/UX-REDESIGN-2026.md` §7.2 与 `docs/operations/export-pricing.md`。
退税率查询、数据完整性检查等其余步骤不变。

- 「数量」与「报关数量」映射同一字段；两列同时出现且冲突时停止。
- 合同号只去首尾空格、统一大小写，不自动增删零，不按柜名替代EXP选票。
- 「捷淞」或公司完整名称进入本方三单；「其他厂家报关」「不报关」「埋单」作为排除项在界面显示，未知或空白报关归属不能静默处理。
- 保留源数量、单位、规格、箱数、毛净重、体积；不把规格默认解释成每箱尺寸并重算体积。
- 公式只读已保存结果，无缓存或Excel错误要求重新计算保存；不执行任意公式。
- 同名记录保持分行和源顺序。只有已确认的品名/规格档案可补HS、要素和货源地；匹配不唯一时要求补证，不做模糊猜测。
- 人工出口价列支持：`出口单价(USD)`、`出口单价（USD）`、`美元单价`、`出口单价`。采购金额按人民币成本处理，不能当作美元售价。

限制：XLSX最大10MB，展开不超过60MB，明细最多5000行，每票最多500行。其他布局不冒充可解析文件。

## 定价顺序和约束

1. 使用本票人工价或Excel已有出口价。
2. 无人工价时查最近同品名、同规格历史报价；本票已保存的人工确认价同样可复用，未确认的本票历史不作参考。
3. 已确认的人工历史价优先保留，偏离当前分类/默认加价目标超过5个百分点时提示复核；普通历史参考价不满足此范围时不自动沿用。
4. 无可靠历史价时复用 `exportPricing.priceFor()`，读取「设置 → 报价规则」中的汇率调整与分类/默认加价，美元单价向上取整。
5. Excel已有价或本票人工覆盖优先保留；偏离目标在界面提示。HS、税库、数量和成本等缺项仍阻止生成。
6. 原模板行金额使用 `ROUNDUP(数量×单价,1)`，页面合计与三单缓存、公式一致。
7. 成功生成时，将人工单价按品名、规格、门店和合同号写入私有报价记录；自动建议价不记为人工确认。下次同品名、同规格优先匹配同门店的最近记录；未区分门店的同批历史出现多个价格时不猜测，并复核当前成本和汇率。

现汇使用现有系统公开汇率查询，失败时填写本票现汇，不暗用示例6.8或旧票汇率。税库按出货日期（缺失时按单证日期）选择生效记录，并核对税务局当前发布版本；版本变化或查询失败时不自动放行。

## 本次人工调整提炼出的取整方案（待选择方向）

本次同时存在上调与下调。可确定的是优先用整洁、容易报价的单价，不能推断为一律向上。示例（非业务报价）：193.2→200、62.2→65、1256→1250、7036→7000、9568→10000、2.62→2.5。

建议档位（推断，尚未启用）：原始美元单价＜10取0.5的倍数；10至100取5的倍数；100至5000取50的倍数；5000及以上取1000的倍数。就近取整与始终向上会产生不同结果，需选择方向后再替换系统唯一取整函数。这些档位不会复现每次人工谈价；本票最终价独立保留，已保存单据不重算。

## 两种利润率

销售额CNY = 三单总额USD × 调整汇率。价差 = 销售额CNY − 采购成本CNY。

- 成本加价率 = 价差÷采购成本。
- 销售毛利率 = 价差÷销售额。
- 毛利率 = 加价率÷（1＋加价率）。例如成本100、售价130，加价30%，毛利率23.08%。

分母不同，不代表少赚一笔钱。此价差测算未计退税、运费、报关费、银行手续费和汇兑变化，不能称为最终净利润。

## 一次性保存模板与资料

管理员在后端目录运行：

```bash
node scripts/setup-export-packet.js \
  --template '/path/to/已确认三单.xlsx' \
  --catalog '/path/to/申报要素目录.xlsx' \
  --refund-dbf '/path/to/cmcode.dbf' \
  --refund-version 2026C \
  --reviewed-on 2026-11-14
```

日期和版本为参数示例，维护时使用实际核对结果。安装器提取已确认的买卖方、条款、商品申报资料和历史单价，清除模板票号、日期和商品金额，形成可复用模板。银行信息、报价和真实商品资料不写入源码、工程记忆或Git。

配置位于实际 `UPLOAD_DIR/export-packet/profile.json`，目录0700、文件0600；覆盖前备份。配置不通过通用系统设置接口返回。发布时须经可信通道放入服务器实际上传根目录，不能只发源码就声称模板可用。

新增确认商品/规格或新税库时重新运行安装器。生成的人工价保存为同目录下不可覆盖的 `quotes-<hash>.json`（0600），重复下载不重复写入；不改变业务库商品和订单。历史单价用于此 Excel 制单流程。

## 实现与验收

- 解析、版本校验、私有配置、原模板生成：`backend/src/services/exportPacketExcelService.js`。
- 共享定价与利润口径：`backend/src/services/exportPacketService.js`。
- HTTP：`POST /api/v1/sales/export-packet/excel/preview` 和 `/generate`，认证后仅ADMIN。
- 页面：出口列表的 `ExportPacketExcelDialog`。单票完整时自动下载，多票选择后生成；改参数后重新计算，关闭后不执行迟到下载。
- 验收覆盖：数量别名/冲突、公式缓存、他方货物、源行不拆、人工价保持、税库/汇率失败、三单一致、来源变化、超过16行的模板扩展、未登录/SALES拒绝、真实浏览器下载及手机操作。

旧 `scripts/prepare_export_packet.py` 已停用；网页复用系统唯一报价实现，不依赖本机WPS缓存路径。
