# 出口清单快速制单与定价 SOP

## 目标

当用户给出一个已在“出货汇总”或系统中确定的 `EXP` 合同号时，以当前 `EXP260010` 工作簿为模板，一次生成并核对：合同、商业发票、箱单、报关明细、报关预录信息。

生成前先出“待确认草案”，确认后才写入线上 WPS 原文件。不得凭商品名称猜 HS、采购成本、退税率、材质、型号或货源地。

## 数据来源顺序

1. 本票范围：优先按 `EXP` 合同号读取 WPS 根目录最新“出货汇总.xlsx”；系统装箱明细仅作交叉核对，不能用旧缓存替代最新云端源。
2. 装箱数据：商品、门店、港口、数量、单位、箱数、毛重、净重、体积、尺寸、柜号、日期、报关公司。
3. 商品申报：以“申报要素目录”和本票已确认资料为候选；HS、申报要素、货源地必须逐项核对，不因退税目的改码。若“出货汇总”只有内部简称（如“铝型材”），允许按同规格已确认本票证据还原正式品名（如“铝型材（喷涂）”），但必须记录证据来源。
4. 采购成本：优先使用装箱明细关联的采购合同/采购金额；匹配不唯一或缺失时停止定价并询问。
5. 历史报价：按“同品名 + 同规格”取最近一票；只有没有可靠历史报价时才使用成本公式。
6. 退税率：每票按出口日期锁定当期国家税务总局出口退税率文库版本，并记录查询结果。不能把旧黑名单永久沿用。
7. 实时汇率：每票重新查询并记录来源、时间和数值；不复用上票汇率。

## 定价规则

报价规则已统一：单价（USD）= 单位采购成本 ¥ × (1 + 加价) ÷ (现汇 − 0.2)，先向上取整到整美元；不足 5 美元就停，否则按个位取最近的 5 的倍数（1、2 舍到 0，3–7 到 5，8、9 进到 10，例 1993.87→1994→1995、1991→1990、1998→2000），普通商品加价 30%、瓷砖等分类按 设置 > 报价规则 单独设置；
缺采购成本时不给建议价，需人工填写。详见 `docs/redesign/UX-REDESIGN-2026.md` §7.2 与 `docs/operations/export-pricing.md`。
退税率查询、数据完整性检查等其余步骤不变。

## 退税资料维护

- 当前基准版本：国家税务总局出口退税率文库 `2026B`。
- 文库不是永久版本。每次新票开始前检查是否发布新版本；新版本发布后保留旧版用于追溯旧票。
- 逐项记录：HS、税库匹配代码、商品名称、退税率、生效日期、税库版本、查询日期。
- 退税率为 `0` 才进入“不可退税、加价不超过 10%”路径；无法匹配时必须阻断，不按可退税处理。
- HS 归类与退税率查询是两件事：先按实物和申报规则确认 HS，再读取该 HS 的退税率。

官方来源：

- https://fgk.chinatax.gov.cn/zcfgk/c102424/c5250255/content.html
- https://shanghai.chinatax.gov.cn/xbwz/wzcx/TYCX_tuiShuiCodeSearch.jsp?SUB=111
- https://fgk.chinatax.gov.cn/zcfgk/c102416/c5235887/content.html

## 一票完整执行顺序

1. 用户确认 `EXP` 合同号。
2. 读取系统/最新出货汇总中的本票明细，冻结行数和顺序。
3. 补齐采购成本关联、规格、箱数、毛净重、体积、单位、门店、港口。
   - 若最新“出货汇总”与已确认 PDF/工作簿在数量、单位、箱数、毛重、净重或体积上冲突，必须列出冲突并阻断；不得静默采用任一方。
4. 按当期税库逐项核对 HS 与退税率。
5. 查询历史报价；无可靠历史报价时按公式算建议价。
6. 输出待确认草案：每项来源、缺失字段、建议单价、总价、利润约束、整票汇总。
7. 阻断项清零后，复制当前 `EXP260010` 模板生成新票文件。
8. 只在一个“本票工作台”写入明细，再联动合同、发票、箱单、报关明细和预录信息；若仍使用当前模板，则按相同冻结顺序逐页写入并回读。
9. 核对合同号、日期、买卖方、贸易术语、包装种类、件数、毛重、净重、体积、总价、币制、港口、柜号。
10. 扫描 `#N/A`、`#REF!`、`#VALUE!`、`#NAME?`、`#DIV/0!`，并渲染查看五张表。
11. 保存线上 WPS 原文件；报关行回传草单后再做 PDF 对比。
12. 正式底单按 `月份/EXP号 日期 门店/底单/` 归档，保留原件和哈希。

## 自动预检命令

工具只读，不会改数据库或 WPS：

```bash
python3 scripts/prepare_export_packet.py \
  --contract EXP260011 \
  --spot-rate 6.8 \
  --export-date 2026-08-13 \
  --refund-dbf /path/to/CMCODE2026B/cmcode.DBF
```

输出 `ready_for_wps_write=false` 时，必须先解决 `blockers`，禁止直接生成正式清单。

## 当前模板的已知限制

- 当前模板仍依赖行号和多表顺序一致，增删行或排序后容易错位。
- “报关明细”仍含手工值，不能把一个页面正确当成五表全部正确。
- “报关预录信息”的商品申报要素和货源地必须逐行引用箱单；发现手工简写或同项不同值时，生成副本必须改为统一引用后再放行。
- 长期目标应是新增单一“本票工作台”，其他五张表仅引用该表；在此改造完成前，每票都必须执行逐页回读。
