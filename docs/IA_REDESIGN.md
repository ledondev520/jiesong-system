# 捷淞系统信息架构重设计

> 设计目标：用户一进来就知道该做什么，核心任务在最短路径上完成。
> 设计原则：不引入新功能，只重组现有功能的组织方式。

---

## 一、当前问题诊断

### 1.1 模块划分不合理

| 问题 | 说明 | 影响 |
|------|------|------|
| 商品档案藏在「采购」下 | `/dashboard/products` 挂在采购模块的 Tab 栏里 | 销售员查商品时以为走错模块；商品是全公司主数据，不应属于单一业务域 |
| 「出口」模块名过窄 | 实际包含出口合同、报关单、HS 编码，但库存、货柜、报关的物流属性被割裂 | 采购员跟进入库/出库找不到入口 |
| 财务子页面过多 | 8 个子页面（概览、报表、收付款、流水、发票、对账、应收、应付）挤在同一层 Tab 栏 | 移动端 Tab 栏溢出，视觉拥挤，常用功能被稀释 |
| 缺少「库存」独立入口 | 库存查询/入出库功能被埋在商品档案页面的「库存」Tab 内 | 用户必须先进商品档案 → 再点库存 Tab，路径深且不符合心智模型 |

### 1.2 导航断裂与深度问题

| 问题 | 说明 | 影响 |
|------|------|------|
| 报关单跳出 Dashboard 布局 | `/customs-declarations` 有独立 `layout.tsx`，切换时侧边栏消失 | 用户从出口合同跳去报关单时，导航上下文完全断裂，像进了另一个系统 |
| 应付/应收被「幽灵重定向」 | `/dashboard/finance/payable` 和 `/dashboard/finance/receivable` 都 302 到 `/dashboard/payments`，但路由仍挂在财务下 | 用户从历史记录或 URL 直接访问时行为不可预期；Tab 栏缺少应收/应付的独立锚点 |
| 采购合同与采购创建命名割裂 | 列表页路由是 `/dashboard/contracts`，创建页是 `/dashboard/purchase/create` | URL 语义不统一，增加心智负担 |

### 1.3 Dashboard 角色模糊

当前工作台试图同时服务「采购员、销售员、老板」三种角色，导致：
- 采购员看到「未发货条目」「待收款 USD」等与自己无关的指标
- 老板被「采购合同起单」的主任务卡片占据首屏，经营数据反而在下层
- 缺少真正的「今日待办清单」，只有数字卡片，点击后跳转的是列表页而非具体待办

### 1.4 移动端导航失衡

- MobileTabBar 固定 4 个主 Tab +「更多」，但当前「更多」里只放了系统管理
- 随着功能增加，「更多」将变成「垃圾桶」，所有不重要的功能都塞进去
- 报关单因为独立布局，在移动端甚至无法通过底部 TabBar 返回主系统

## 二、建议的信息架构

### 2.1 核心思路：按「业务对象 + 物流实体」重组

外贸企业的日常语言是：
- **买**（采购合同、供应商）
- **卖**（出口合同、客户门店）
- **货**（库存、货柜、报关）
- **钱**（应收、应付、收付款、报表）

现有 5 大模块中，「经营中台」作为 Dashboard 没问题，但「采购」和「出口」的边界把「货」的相关功能撕碎了。建议把「货」独立为「仓储物流」模块，让采购和销售聚焦于合同本身。

### 2.2 新六模块架构

```
工作台（Dashboard）
├── 今日待办（角色化）
├── 经营数据（老板/财务视角）
└── 执行看板（未发货、采购清单）

采购管理
├── 采购合同
├── 供应商
└── 采购建议

销售管理
├── 出口合同
├── 客户门店
└── 退税管理

仓储物流（新增/重组）
├── 库存总览
├── 入库/出库
├── 货柜装箱
├── 报关单
└── HS 编码

资金财务
├── 资金概览
├── 收付款记录
├── 应收账款
├── 应付账款
├── 银行流水
├── 发票台账
├── 财务报表
└── 对账分析

系统设置（仅管理员可见，移动端收进「更多」）
├── 基础数据
│   ├── 商品档案
│   ├── 港口管理
│   ├── 报关公司
│   └── 汇率配置
├── 用户管理
├── 系统配置
├── 数据导入/导出
├── AI 日志
├── 系统日志
└── 关于
```

### 2.3 改动说明与理由

| 改动 | 理由 |
|------|------|
| 新增「仓储物流」模块 | 库存、货柜、报关在真实业务中是同一根链条（货物从入库 → 装箱 → 报关 → 出海），原架构把它们拆给了采购（商品档案里的库存Tab）、出口（货柜在出口合同详情里）、独立路由（报关单），导致采购员和跟单员找功能时迷失 |
| 商品档案移至「系统-基础数据」 | 商品是全局主数据，不是采购专属。日常创建合同时通过选择器查询，不需要访问商品列表页；列表页的主要用途是管理员维护商品信息 |
| 报关单纳入 Dashboard 布局 | 将 `/customs-declarations` 迁移至 `/dashboard/customs-declarations`，统一侧边栏和 Tab 栏上下文，消除导航断裂 |
| 财务增加「应收/应付」独立 Tab | 现有应收/应付页面 302 到收付款页，对财务人员不友好。应收应付是「看欠款」，收付款是「做记录」，两个动作应分开展示，或通过同一页面的不同视图切换 |
| 出口模块改名为「销售」 | 更贴近业务语言。出口合同是销售行为，模块内还包含客户门店（销售对象），「出口」一词过于海关导向 |

### 2.4 最小化迁移路径

为控制风险，可按以下优先级分步实施：

1. **P0（立即做）**：将报关单路由收归 Dashboard 布局下，修复导航断裂
2. **P0（立即做）**：在侧边栏新增「仓储物流」模块入口，将库存相关页面从商品档案中「提拔」出来
3. **P1（本周做）**：调整 Dashboard 为角色化视图，不同角色首屏内容不同
4. **P1（本周做）**：财务 Tab 栏分组（资金动作 vs 资金记录 vs 分析）
5. **P2（后续做）**：商品档案迁移至系统-基础数据，原采购模块 Tab 栏移除商品档案入口

## 三、核心用户流程

### 3.1 采购员的一天

```
打开系统 → 工作台「今日待办」
         → 【有待起草采购？】→ 点击「新建采购合同」→ 选择供应商/商品 → 保存生成 CG 编号
         → 【有待收货？】→ 点击「仓储物流」→ 入库操作 → 扫描/选择商品 → 确认入库
         → 【有待付款？】→ 点击「资金财务」→ 收付款记录 → 新增付款 → 关联采购合同
         → 【供应商信息不全？】→ 点击「采购」→ 供应商 → 补充联系方式/银行信息
         → 下班前：回工作台扫一眼「执行看板」确认无遗漏
```

**最短路径设计**：
- 采购员 80% 的操作是「起草采购合同」和「确认入库」，这两个动作在工作台首屏直接可达（按钮 + 待办卡片）
- 供应商查询在创建合同时通过选择器完成，不需要去供应商列表页

### 3.2 销售员的一天

```
打开系统 → 工作台「今日待办」
         → 【有新订单？】→ 点击「新建出口合同」→ 选择门店/商品 → 智能定价 → 保存生成 EXP 编号
         → 【有待补录出口参数？】→ 点击待办条目 → 补录箱数/毛重/体积 → 推进装柜
         → 【要安排装箱？】→ 点击「仓储物流」→ 货柜装箱 → 选择出口合同 → 录入明细
         → 【要报关？】→ 点击「仓储物流」→ 报关单 → 关联出口合同 → 录入报关信息
         → 【门店欠款？】→ 点击「资金财务」→ 应收账款 → 查看未结清 → 记录收款
         → 下班前：回工作台确认「待补录出口」清零
```

**最短路径设计**：
- 销售员的核心链路是「出口合同 → 补录参数 → 装柜 → 报关 → 收款」，新架构下这条链路的所有节点都在「销售」和「仓储物流」两个模块内，无需跨到「采购」模块
- 报关单从独立布局回归后，销售员可以在同一导航体系内完成报关操作

### 3.3 老板的一天

```
打开系统 → 工作台「经营数据」
         → 【看整体】→ 扫一眼资金概览卡片（应收/应付/现金流）
         → 【看风险】→ 下滑到「紧迫预警」（超期未收款、库存积压）
         → 【查账】→ 点击「资金财务」→ 财务报表 / 对账分析
         → 【审批】→ 点击工作台「待审批」卡片 → 查看异常合同 → 批准/驳回
         → 【查具体合同】→ 顶部搜索 → 输入合同号/供应商名 → 直达详情
```

**最短路径设计**：
- 老板不应被「起草采购合同」的主任务卡片打扰，首屏应该是「钱、货、风险」
- 审批动作直接在工作台完成，不需要跳模块

### 3.4 财务人员的一天

```
打开系统 → 工作台「今日待办」
         → 【记录收款】→ 点击「资金财务」→ 收付款记录 → 新增收款 → 关联出口合同/门店
         → 【记录付款】→ 点击「资金财务」→ 收付款记录 → 新增付款 → 关联采购合同/供应商
         → 【对账】→ 点击「资金财务」→ 对账分析 → 上传银行流水 → 系统匹配
         → 【出报表】→ 点击「资金财务」→ 财务报表 → 导出三表
         → 【查发票】→ 点击「资金财务」→ 发票台账 → 检索/核销
```

**最短路径设计**：
- 财务的核心是「记录 → 核对 → 报表」，三个动作在「资金财务」模块内闭环完成
- 收付款记录作为高频入口，应放在财务 Tab 栏第二位（仅次于概览）

#### 仓储物流（WAREHOUSE_TABS，新增）
```

```
- 库存总览：复用现有商品档案页的 InventoryTab，提拔为独立页面 `/dashboard/inventory`

- 货柜装箱：现有出口合同详情内的装箱功能，也可在此提供全局视角
- 报关单：从独立路由 `/customs-declarations` 迁移至 `/dashboard/customs-declarations`
- HS 编码：从出口模块移入

#### 资金财务（FINANCE_TABS，重组）
```
[资金概览] [收付款] [应收账款] [应付账款] [银行流水] [发票台账] [财务报表] [对账分析]
```
- 应收/应付恢复为独立 Tab，不再 302 到收付款
- 如果移动端 Tab 栏溢出，可采用「更多」下拉或分组为：
  - 动作层：收付款
  - 记录层：应收、应付、银行流水、发票
  - 分析层：资金概览、财务报表、对账分析

#### 系统设置（ADMIN_TABS，重组）
```
[系统配置] [用户管理] [基础数据] [数据导入] [AI 日志] [系统日志] [项目驾驶舱] [关于]
```
- 新增「基础数据」Tab，内含商品档案、港口、报关公司、汇率配置的子导航（可用二级 Tab 或侧边子菜单）

### 4.3 移动端 MobileTabBar（5 + 更多）

## 五、Dashboard 重设计思路

### 5.1 总体策略：统一框架 + 角色化内容

不建议做「完全独立的四个 Dashboard」，维护成本高且用户切换角色时（小公司一人多岗）会困惑。

推荐策略：
- **统一框架**：所有角色看到的布局结构相同（速览卡片 → 主任务 → 执行看板）
- **角色化内容**：根据 `user.role` 动态渲染每个区块的具体内容
- **可折叠区域**：老板的经营数据区对采购员默认折叠，反之采购员的主任务区对老板降低视觉权重

### 5.2 区块设计

#### 区块 A：今日速览（4 卡片，所有角色可见，内容不同）

```
┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│ 待起草采购   │ │ 待补录出口   │ │ 未发货条目   │ │ 待收款(USD) │
│     3       │ │     5       │ │     13      │ │   $1.13M    │
└─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘
```

- **采购员视角**：前两张卡片放大，后两张缩小或折叠（变为次要指标）
- **销售员视角**：「待补录出口」放首位，「待收款」放大
- **老板/财务视角**：四张等权展示，或替换为「本月利润」「现金流」「逾期应收」「在途库存」等经营指标

#### 区块 B：我的主任务（1-2 个核心流程入口，角色化）

```
【采购主线】采购合同起单 → 发给供应商 → 回签归档
   [新建采购合同] [新增供应商] [跟进合同]

【出口主线】出口合同创建 → 补录参数 → 装柜报关
   [新建出口合同] [去补录出口参数] [上传财务报表]
```

- **采购员**：只显示「采购主线」
- **销售员**：只显示「出口主线」
- **老板**：显示「财务上报」卡片（上传报表、看异常），采购/出口主线折叠或隐藏

#### 区块 C：今日待办清单（具体条目，可点击直达）

现有 Dashboard 只有数字卡片，点击后跳到列表页。建议增加「可执行待办列表」：

```
今日待办
├── CG2600012  供应商：米尔皮塔  [继续起草] →
├── EXP2600008 门店：禧瑞都      [补录箱数] →
├── EXP2600005 已逾期 15 天      [记录收款] →
└── ...
```

- 数据来源：各模块的「草稿/待处理」状态聚合
- 交互：点击后直接跳到对应合同的详情页并定位到待处理字段
- 权限过滤：采购员看不到出口待办，反之亦然；老板看到全部

#### 区块 D：经营数据（仅老板/财务默认展开，其他角色折叠）

```
经营数据 ▼
├── 月度收支趋势（折线图）
```
