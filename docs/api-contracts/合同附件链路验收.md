# 合同附件 HTTP / SQLite 链路验收

基线：`967c837e75d3aefc908d15e92ba7d89d4d9ee1f1`。所有验收均在隔离 SQLite 和临时 `UPLOAD_DIR` 中执行，附件内容完全生成，不使用业务文件或生产环境。

## 红例与修复

- 含“退税出货清单确认:”描述的附件经通用下载入口对 SALES 返回 403，但旧销售下载入口返回 200。通用及旧采购/销售下载、删除统一调用 `fileService.assertFileAccess`，沿用既有 ADMIN/FINANCE 边界
- 不存在合同的 multipart 上传在三个入口均返回 500，且留下本次文件。上传服务先核对合同；失败返回 404 并仅清理当前新上传，不触及其他版本
- 未知合同类型会默认为采购并返回 201。统一上传及列表显式拒绝未知类型；未指定类型仍保留 PURCHASE 默认
- 不支持 MIME 或超过上传上限返回 500。格式过滤与 Multer 输入限制改为 400，服务器内部异常仍为 500

## 已验证矩阵

| 流程 | 验收内容 | 结果 |
|---|---|---|
| 普通上传 | 通用采购、通用销售、旧采购/销售 multipart 写入 | 201；真实数据库记录及存储字节可连续访问 |
| 版本 | 同名再次上传 | 新 ID / 新路径；原版本保留，不引入替换接口 |
| 存储 | 已登记上传 | 文件 0600，所属目录 0700 |
| 上传前置目录 | Multer 新建/已有日期目录、mkdir/chmod 故障 | 写流开始前目录 0700；故障经回调拒绝启动流，根目录共享策略不变 |
| 异步查询前置 | 首次合同 findUnique 回调中检查权限 | 文件 0600、日期目录 0700；不声称整个流阶段文件均为 0600 |
| 普通读取 | SALES / PURCHASE / WAREHOUSE / BOSS / FINANCE | 通用列表及通用、旧下载成功；下载字节及文件名一致 |
| 普通写入 | SALES / PURCHASE / WAREHOUSE / FINANCE | 上传、普通删除成功，现有角色范围不变 |
| 拒绝写入 | BOSS | 通用及旧采购/销售上传、删除均 403；记录和文件不变 |
| 认证 | 无凭证、停用用户；JWT 声称 ADMIN 但实际普通角色 | 无凭证/停用 401；实际数据库角色决定权限 |
| 上传失败 | 合同不存在、未知类型、未选文件、MIME 错误、生产图分类错误、超过 10MB | 404 / 400；原版本及现有字节不变，新失败文件不留存 |
| 服务故障 | chmod / 数据库写入 / 上传期间合同消失 | 不建立有效新附件；清理当前上传，既有文件哨兵保留 |
| 清理故障 | unlink 失败 | 原错误保留；仅固定故障日志，不记录路径或内容 |
| 财务确认附件 | 实际受限归档的合成 XLSX；通用/旧销售下载与删除 | SALES / PURCHASE / WAREHOUSE / BOSS 均 403；记录及文件保留 |
| 财务确认附件 | ADMIN / FINANCE | 下载字节一致；授权删除通过 |
| 旧采购财务入口 | 合成保护描述附件 | SALES 下载与删除 403，ADMIN 通用删除通过 |
| 船司原件 | 已有 PackingListCheck 引用 | 通用与旧销售删除 409；原件及引用保留，可正常读取 |
| 旧采购删除 | 原有物理归档留存约定 | 仅移除附件记录；保留既有物理文件，不改变留存政策 |
| 缺失文件 | 缺记录、跨合同类型旧下载、物理文件丢失、重复删除 | 404；其他记录及文件不变 |
| 静态旁路 | app/routes 源码及无认证 /uploads/合成路径 | 无公共附件静态挂载；实际 HTTP 404 |

## 运行

`cd backend && npm run test:db` 已包含 `contract-attachments.integration.js`；也可单独执行该测试。完整服务测试另执行 `npm test`。HTTP fixture 不豁免或修改全局 100/min 限流，并断言请求数未超过预算。

前端文件选择取消、失败重试、默认 Bearer 下载/预览另由组件和服务测试验证；此 HTTP 验收不声称执行过浏览器、生产文件或正式税务提交。
