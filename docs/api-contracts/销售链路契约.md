# 销售链路 API 契约（V1）

## 目的/边界/职责
- 目的：明确销售链路接口契约，支持前后端稳定联调。
- 边界：覆盖 `/api/v1/sales` 及其装箱相关子资源。
- 职责：为销售合同、装箱与状态流转提供统一接口基线。

## 通用约定
- Base URL：`/api/v1`
- 鉴权：`Authorization: Bearer <token>`
- 响应结构：沿用统一 `{ code, message, data }`
- 列表查询关键字参数：`keyword`（与后端 `salesController.list` 保持一致）

## 核心接口

### 列表/详情/创建/更新/删除
- `GET /sales`：分页 + `status/storeId/keyword` 筛选
- `GET /sales/:id`：获取详情（含装箱与明细）
- `POST /sales`：创建销售合同（`exchangeRate` 必填）
- `PUT /sales/:id`：更新销售合同
- `DELETE /sales/:id`：删除销售合同

### 销售与装箱明细
- `POST /sales/:id/items`：添加销售明细
- `POST /sales/:id/packing-items`：添加装箱明细
- `PUT /sales/:id/packing-items/:itemId`：更新装箱明细
- `DELETE /sales/:id/packing-items/:itemId`：删除装箱明细

### 其他能力
- `PUT /sales/:id/status`：更新合同状态
- `GET /sales/options/next-no`：获取下一个销售合同号（`EXP` 前缀）
- `POST /sales/calculate-price`：计算推荐售价
